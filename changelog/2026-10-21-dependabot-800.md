# Dependabot sweep: markdown-it, prosemirror-view, vitest 4, Go 1.26 builder

**Date:** 2026-10-21
**Type:** infra
**Version:** v0.5.2
**Author:** claude-code

## What changed

Web dependencies bumped within their lines: `markdown-it` 14.3.3 (pulls `linkify-it` 5.0.2),
`prosemirror-view` 1.42.6, `vite` 6.4.5, plus transitive `postcss`, `nanoid`, `browserslist`,
`baseline-browser-mapping`, `source-map-js`, `form-data`. `vitest` moved 2.1 -> 4.1 (dev only;
all 40 tests pass unchanged). The Go builder stage moved to `golang:1.26-alpine`.

## Why

Dependabot alerts on `web/package-lock.json` (fisherevans/nottingham-cloud#800). The ones that
reach the shipped bundle are `markdown-it`/`linkify-it` (quadratic-time DoS on crafted markdown -
the editor parses every post through it), `prosemirror-view` (XSS in paste handling - the editor
is a ProseMirror view), all cleared here. scribe sits behind OIDC on `scribe.fisher.sh` and only
edits Fisher's own blog repo, so none were practically exploitable, but they are cheap patch bumps.
Everything else (vite, vitest/tinypool, esbuild, postcss, form-data, browserslist) is dev/build
tooling that never reaches the image's embedded `dist`.

## Context / alternatives

`@tiptap/core` (`mergeAttributes` `__proto__` key, medium) is only fixed in tiptap 3.30.4. The
v2 -> v3 move changes the BubbleMenu, table and drag-handle APIs around `markdown.ts`, the riskiest
code in the repo, so it is left for a deliberate migration rather than a security sweep. The
attribute objects it merges come from scribe's own markdown parser over Fisher's content.

The lockfile was regenerated with npm 11: npm 10.9's arborist crashed (`reading 'edgesOut'`)
resolving vitest 4's peer set. `npm ci` on npm 10 reads the result fine.
